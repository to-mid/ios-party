# MIX 2 单轮修改与交付

每轮只写清四项：**依据、改动、预期、实际结果**。允许多个观察点，但只处理一个待验证原因。
设备操作按说明手动执行。完整内核编译在云端，本机仅做轻量检查和交付校验。

## 小 bug 默认走快速路径

2026-10-24 起优先采用快速迭代，按改动范围选择必要检查：

| 修改类型 | 本轮检查 | 新增测试 |
| --- | --- | --- |
| 日志、版本标签、简单路径或接线 | 语法、实际受影响命令、必要打包校验 | 通常不新增 |
| 已定位的局部 bug | 相关模块已有测试、受影响构建和一个可观察验收点 | 有价值时只补能复现该 bug 的定向用例 |
| 共享 ABI、内存/DMA 所有权、跨模块行为 | 必要边界检查、完整回归或相应运行资格 | 按实际风险覆盖 |

相关检查一旦通过，立即进入构建、打包和交付；与当前 bug 无关的审计、
守卫、抽象、文档扩展及优化放到后续。已有测试通过后，只有新改动、
失败或未解决疑点才重跑。完整回归集中在共享行为修改或集成里程碑，
不把每次小修都变成一次全项目验证。

小修约 10–15 分钟仍未形成可验证改动时，说明具体卡点和最小下一实验，
避免悄悄扩大任务。等待云端期间只做不阻塞交付的独立工作；
测试和打包完成后不继续扩展代码而延迟交包。
快速路径仍保留必要的源码编译、镜像一致性、容量与硬件前提检查。

## 按改动选择最小构建

| 改动范围 | 必须构建 | 保持不变 |
| --- | --- | --- |
| loader 的检查、USB 上传或窗口接管 | 小 EFI loader，重打启动容器 | 内核、系统卷、UEFI（若交接契约没变） |
| EFI 入口与 USB 连接 | 入口 EFI，重打启动容器 | 内核、系统卷、未改的固件体 |
| PEI/HOB/早期内存布局 | UEFI 固件体、相应入口与 loader，重打启动容器 | 内核及原系统卷 |
| XNU 源码/配置 | 云端内核构建及受影响资格 | 未改的用户态输入 |
| 根卷内容/用户态 | 用户程序、系统卷及相应运行资格 | 未改的内核 |

复用必须绑定准确哈希和接口版本。复用旧构建不等于复用所有运行资格。
不用每次重新下载 IPSW，也不为纯 loader 改动重跑完整 APFS 系统构建。

## 固定的交付入口

下载本轮云端 artifact 后，只执行一次：

```sh
python3 tools/deliver_chiron_hackios.py \
  --artifact dist/本轮下载目录 \
  --change '本轮实际改动' \
  --expect '手机上能明确观察的通过或失败条件'
```

版本号取自镜像中的默认菜单条目，不手工给旧镜像改名伪装成新版。
入口自动执行容器 SHA-256/legacy SHA-1、FAT 读回、EFI/loader/payload 哈希、
实际固件身份、候选平台和内存预算的一致性检查。

默认输出至 `dist/mix2-hackios/`：

- `MIX2-HackiOS-HK*.img` 和对应 `manifest-hk*.json`。
- `delivery-hk*.json`，仅声明本轮静态校验。
- `TEST-HK*.zh-CN.md`，只说明本轮改动、预期、两阶段启动命令及需要的反馈。
- 版本化上传脚本，避免替换旧版本依赖。
- `latest-candidate.json`，在所有检查及文件交付成功后才更新。

已有同版本不同字节时拒绝覆盖，保留上一版。工具不启动、上传、重启或刷写手机。
系统卷不重复复制或在每次交付时重新哈希；真正上传前由现有上传工具完整核验。
入口不重复证明源码来源、QEMU 或真机资格；这些来自绑定的云端记录及实际手机观察。

## 每轮结束的最小回复

只需交付：

1. **改了什么**：一句话。
2. **测试哪个文件**：版本化绝对路径。
3. **看什么**：一个明确的阶段、容量、日志或行为。
4. **结果如何**：构建/静态/QEMU/真机分别记录，没有证据即写未验证。

上机后收集一次完整反馈再改下一版，避免同时交付多份含义不清的候选。
出现新问题时优先使用已经取得的日志，不重复扫描整个源码树。
每个检查点都必须能改变下一步决策；无关的额外审计不放在交付关键路径。

## 云端等待的配套优化

`hackios-reference.yml` 已在本地接入依赖预检、四个独立下载缓存、
命令/阶段耗时和失败日志收集。工具链与三份 Apple 原始映像分别绑定固定
SHA-256；单个文件有效时，即使本轮其他阶段失败也可保存。缓存上传安排在运行检查后，
避免首轮先等大文件缓存上传才能开始 QEMU。

缓存不包含生成的内核、APFS 系统卷或运行通过结果，不改变现有验收要求。
这些流水线改动尚需随集成流程同步后在云端验证；本地测试不能证明缓存已命中或节省多少时间。
本轮只用历史 HK6 产物演练自动交付，结果位于 `out/chiron-delivery-demo/`，
没有重新构建固件，也没有执行设备命令。
